vpnbox

A free VPN for Linux that needs no account, no key, and no payment.

Python 3.8+ · one file, stdlib only · v1.0.0-beta2 (Oct 2026) · OpenVPN + systemd-resolved — source

Problem

The public internet already runs an underrated resource: the VPN Gate relay experiment run by the University of Tsukuba — thousands of volunteer-run VPN servers, free, no signup. But consuming it properly means mashing three things together by hand: a mirror-fetch of a live server list, a ranking pass that knows which server is actually reachable, and a full-tunnel OpenVPN setup that doesn't leak DNS. vpnbox turns that mash-up into one command. "Just give me a working VPN, in any country, for free" is the whole spec.

Constraints

  • One Python file, standard library only. No pip installs for the app itself — download, run install.sh, get a vpn command.
  • vpnbox never reimplements a protocol. OpenVPN is the datamover; vpnbox prepares config, routes, and DNS, and drives the binary. openvpn-systemd-resolved carries pushed DNS settings to the system so nothing leaks.
  • Volunteer servers die by the hour. The design assumption is unreliable infrastructure: ranking, fail-fast, and verification are features, not extras.
  • Honest output. Where you connect is printed — exit IP plus city/ISP — and if it doesn't match the country you asked for, vpnbox warns you rather than pretending.

Architecture

vpn (single stdlib file)
  ├─ refresh ─→ VPN Gate live list (fetched on demand, geolocated)
  ├─ rank ────→ real ping + speed measured before ranking
  ├─ sites ───→ 29 platforms · 239 offices · 31 countries
  │             (addresses OSM-geocoded, cached forever)
  └─ connect ─→ best candidate through openvpn (full tunnel)
        ↓ (interfaces, routes, DNS = system state → sudo)
  systemd-resolved pushes DNS → nothing plaintext-leaks
  ↳ status: exit IP + city/ISP verified after connect
  ↳ fail-fast: dead server? try next best up to 3 times

The signature feature

Beyond country and city targeting, vpnbox knows the worldwide office locations of 29 platforms — 239 offices across 31 countries — so you can ask to appear near one.

vpn sites                              # the whole catalogue
sudo vpn connect --site meta           # near Meta's primary HQ (Menlo Park)
sudo vpn connect --site meta --office Seoul
sudo vpn connect --site meta --office all   # nearest to ANY of its 29 offices

--site alone means the primary HQ, predictable by design. Office addresses are geocoded precisely — one polite request per second to OpenStreetMap's Nominatim, its policy — then cached forever, degrading gracefully to city-level coordinates if OSM is unreachable. Distance is balanced with reality: offices bucket into distance tiers (≤40 / ≤150 / ≤500 / ≤1500 km) around each candidate server, and within a tier ping, speed, and UDP preference decide — so "4 km from the Bangkok office" is still the fast alive server near there, never a close-but-dead one.

Engineering decisions

  • Browse or don't. vpn countries / vpn servers JP drill down by country, city, ISP, ping, speed — or vpn connect skips browsing entirely and takes the best server anywhere.
  • Fail fast, try the next. If a volunteer server refuses the handshake, vpnbox fails on it and tries the next best candidate, up to three times by default (--max-tries). Pin an exact entry with --index, skip a flaky one with --skip, and when a requested country has no live pool, --nearest offers the closest one that is.
  • sudo only where it must be. VPN interfaces, routes, and DNS policies are system state — the one place vpnbox insists on root, and it prints the exact command to copy-paste if you forget.
  • Caches with clear ownership. Server and office state live in ~/.cache/vpnbox; runtime state under /var and /run is wiped by uninstall.sh --purge.

Status

v1.0.0-beta2, shipped 2026-10-20. The core paths work end to end: refresh → browse → connect → verify → disconnect, with country/city and platform-office targeting. It is a beta: behaviors are still being pinned down before a 1.0. Per-test-suite numbers will land with the release, not before.

Lessons

Building on someone else's already-running infrastructure (the volunteers + OpenVPN + a university project) is mostly a translation job: turn a CSV mirror, a ping timeout, and a routing table into one honest CLI. The hard part isn't trust, it's truthfulness — the tool can't improve the network, so all it can offer is measurement (real ping, real speed), fail-fast behavior, and telling you exactly where you landed.
